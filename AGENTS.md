# Project Instructions

## Overview

This is a small Vite + TypeScript darts app with three HTML entry points:

- `src/index.html`: start screen, game type selection, player names, leg count.
- `src/game.html`: 501 game screen with generated target sectors and player table.
- `src/training.html`: sector training screen.

The app is client-only. State is stored in `localStorage` under the `game-setting`
key and passed between pages by navigation.

## Commands

- Install dependencies with the package manager already present in the workspace.
  The repository currently has `package.json`, `node_modules`, and an untracked
  `bun.lock`.
- Run development server: `npm run dev`.
- Build and type-check: `npm run build`.
- Preview production build: `npm run preview`.

There is no dedicated test or lint script. Use `npm run build` as the baseline
verification after TypeScript, HTML, SCSS, or Vite changes.

## Architecture

- `src/js/main.ts` initializes the start screen and resets `game-setting`.
- `src/js/count-players.ts` controls the start form, writes `{ countLags, players }`
  to `localStorage`, and navigates to `game.html`.
- `src/js/game/index.ts` owns 501 game state, turn flow, bust handling, undo,
  leg wins, and final restart/cancel prompts.
- `src/js/game/game-paint.ts` generates the target sector markup and player table.
- `src/js/training/training-sector.ts` owns the sector training state through a
  `TrainingSector` class and a `Proxy` for UI updates.
- `src/js/types.ts` contains shared TypeScript interfaces.
- `src/scss/style.scss` contains global variables and shared UI styles.
- `src/scss/players.scss`, `src/scss/game.scss`, and `src/scss/training.scss`
  style their matching pages.

## Coding Guidelines

- Keep TypeScript strict-clean. The project enables `strict`, `noUnusedLocals`,
  `noUnusedParameters`, `erasableSyntaxOnly`, and `noUncheckedSideEffectImports`.
- Preserve explicit `.ts` extensions in local imports, matching the existing
  `allowImportingTsExtensions` setup.
- Prefer small DOM guards with `console.warn` for missing required elements,
  consistent with existing game code.
- Keep page-specific behavior in its current module instead of introducing a
  shared framework or routing layer.
- Preserve the current `localStorage` contract unless the matching readers and
  writers are updated together.
- When changing game logic, check turn count, bust behavior, undo history, leg
  reset, and final match win behavior together; these are tightly coupled.
- When changing training logic, check reset, undo, sector switching, bull mode,
  and the 10-attempt completion flow together.
- Avoid unrelated formatting churn. The codebase uses 4-space indentation in
  TypeScript and 2-space indentation in SCSS.

## UI Notes

- The visual style is dark, high-contrast, and simple, with CSS variables in
  `style.scss`.
- The game target is generated by DOM markup plus SCSS positioning; sector order
  lives in `paintTarget`.
- Mobile behavior is mostly handled at `576px`; tablet target sizing uses `768px`.
- Keep buttons and controls touch-friendly because the game screen is designed
  for direct tapping.

## Git Notes

- Do not revert unrelated user changes.
- `dist/` is generated and not tracked.
- `bun.lock` is currently untracked; leave it alone unless the user asks to
  decide the package-manager lockfile policy.
